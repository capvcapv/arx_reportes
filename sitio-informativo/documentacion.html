CONCEPTOS BÁSICOS

¿Qué es ARX Reportes?

Es una aplicación web que convierte sentencias de consulta de SQL Server en reportes disponibles desde el navegador. Un administrador prepara la consulta y sus filtros; el usuario final solamente captura parámetros, visualiza resultados y exporta a Excel.

Uso libre

ARX Reportes puede utilizarse sin cargos por usuario. Se instala en infraestructura propia y la información permanece bajo el control de la organización.

Capacidades principales

  • Múltiples conexiones e instancias de SQL Server.
  • Consultas que comienzan con SELECT o WITH.
  • Parámetros manuales o seleccionados desde un catálogo SQL.
  • Usuarios con permisos individuales por reporte.
  • Sumatorias, filas destacadas y exportación a Excel.
  • Transferencia de reportes mediante archivos JSON.

PRIMERA EJECUCIÓN

Inicio rápido

Para desarrollo o una prueba local necesitas Git, el SDK de .NET compatible con la versión del proyecto y acceso de red a SQL Server.

  1. 1
    Descarga o clona el repositorio

    Abre GitHub para descargar el ZIP, o clónalo desde una terminal:

    git clone https://github.com/capvcapv/arx_reportes.git
cd arx_reportes
  2. 2
    Configura la clave administrativa

    Define una contraseña segura mediante la variable Admin__Password. No conserves la contraseña inicial al publicar.

  3. 3
    Inicia la aplicación
    dotnet restore
dotnet run
  4. 4
    Abre la dirección mostrada

    Entra a Administración, registra una conexión y utiliza el botón de prueba antes de crear reportes.

SERVIDOR DEL CLIENTE

Publicación en Windows

Para generar un paquete independiente para Windows de 64 bits, ejecuta desde la carpeta del proyecto:

dotnet publish -c Release \
  -r win-x64 \
  --self-contained true \
  -o ./publish/win-x64

Copia todo el contenido de publish/win-x64 al servidor. Para una prueba temporal puedes iniciar ArxReportes.exe; para operación permanente utiliza IIS, un Application Pool exclusivo y un certificado HTTPS.

Permiso necesario

La identidad que ejecuta el sitio necesita permiso de modificación únicamente sobre App_Data, ya que ahí se guarda el catálogo y las llaves de protección.

Al actualizar

Detén el sitio, respalda la instalación y reemplaza los binarios, pero conserva App_Data. Esa carpeta contiene la configuración de la instalación.

DISEÑADOR

Creación de reportes

Cada reporte tiene nombre, descripción, conexión, sentencia SQL, tiempo máximo de ejecución, orden y estado. Por seguridad funcional, la consulta debe iniciar con SELECT o WITH.

SELECT
    D.CFOLIO AS Folio,
    D.CFECHA AS Fecha,
    D.CRAZONSOCIAL AS Cliente,
    D.CTOTAL AS Total
FROM admDocumentos AS D
WHERE D.CFECHA BETWEEN @FechaInicial AND @FechaFinal
ORDER BY D.CFECHA DESC;
Usa parámetros

No concatenes texto capturado por el usuario dentro de la consulta. Escribe @NombreParametro y registra el mismo nombre, sin @, en la configuración.

Parámetros disponibles

Los parámetros permiten reutilizar una consulta sin pedir al usuario que modifique SQL.

FechaDía inicial, final o fecha de corte.
FechaHoraFecha con hora precisa.
BooleanoOpciones Sí o No.
ConsultaSelección tomada de otro catálogo SQL.

Parámetro obtenido desde otra consulta

Utiliza el tipo Consulta para que el usuario seleccione un cliente, concepto u otro registro sin conocer su identificador interno.

SELECT
    CIDCLIENTEPROVEEDOR,
    CCODIGOCLIENTE,
    CRAZONSOCIAL
FROM admClientes
ORDER BY CRAZONSOCIAL;

Configura CIDCLIENTEPROVEEDOR como columna de valor y CCODIGOCLIENTE, CRAZONSOCIAL como columnas visibles.

PRESENTACIÓN

Sumatorias y filas destacadas

Sumatorias

Activa Mostrar sumatorias de columnas numéricas para agregar un pie con el acumulado de cada columna numérica.

Destacar filas

En Valores de la primera columna que se destacarán, escribe un valor por línea. Cuando la primera columna coincida, la fila recibirá un sombreado especial tanto en pantalla como en Excel.

SUMA 80%SUMA 20%TOTAL COBRANZA CORRIENTE

La comparación ignora mayúsculas, minúsculas y espacios exteriores, pero el resto del texto debe coincidir.

ACCESO

Usuarios y permisos

Desde Administración → Usuarios puedes crear cuentas, activarlas o desactivarlas y elegir individualmente qué reportes verá cada persona.

  • El administrador conserva acceso a la configuración completa.
  • El usuario final sólo encuentra reportes que le fueron asignados.
  • Las rutas directas vuelven a comprobar el permiso en cada solicitud.
  • Las contraseñas de usuarios se guardan como hash y no pueden recuperarse.

PORTABILIDAD

Importar y exportar reportes

En la tabla administrativa, descarga un reporte como JSON. El archivo contiene SQL, parámetros, totales, destacados y demás opciones, pero nunca incluye credenciales ni cadenas de conexión.

Para importarlo en otra instalación puedes seleccionar el archivo o pegar directamente su contenido. El sistema genera un nuevo identificador y añade fecha y hora al nombre para evitar reemplazos accidentales.

Guía para IA

Descarga la guía JSON incluida en la sección de reportes y entrégala a una IA junto con el esquema autorizado de tu base. La guía describe el contrato completo de importación.

CONTPAQi + SQL SERVER

Uso con bases de CONTPAQi

ARX Reportes es útil para explotar información operativa alojada en SQL Server por productos CONTPAQi. Puedes construir reportes sobre documentos, clientes, conceptos y clasificaciones disponibles en tu empresa.

Proyecto independiente

No es un producto oficial ni una integración certificada por CONTPAQi. Los nombres de tablas y columnas pueden cambiar según producto, versión o configuración.

Recomendaciones

  1. Trabaja primero sobre una copia o ambiente de pruebas.
  2. Solicita al responsable de sistemas una cuenta SQL dedicada de sólo lectura.
  3. Evita consultas sin filtros sobre tablas grandes.
  4. Valida importes, cancelaciones y relaciones contra reportes conocidos.
  5. No realices INSERT, UPDATE, DELETE ni cambios de esquema.
SELECT TOP (100)
    CIDCLIENTEPROVEEDOR,
    CCODIGOCLIENTE,
    CRAZONSOCIAL
FROM admClientes
ORDER BY CRAZONSOCIAL;

OPERACIÓN RESPONSABLE

Seguridad y respaldos

  • 01
    Cuenta SQL de sólo lectura

    La protección más importante ocurre en SQL Server. Concede únicamente acceso a las bases y objetos necesarios.

  • 02
    HTTPS obligatorio

    Instala un certificado válido cuando el sitio esté disponible en la red.

  • 03
    Respalda App_Data

    Guarda juntos catalog.json y la carpeta keys. Sin las llaves no podrán descifrarse las contraseñas SQL protegidas.

  • 04
    Actualiza credenciales

    Cambia la contraseña administrativa inicial y desactiva usuarios que ya no requieren acceso.

DIAGNÓSTICO

Solución de problemas

No conecta con SQL Server+

Confirma servidor e instancia, credenciales, nombre de base, protocolo TCP/IP, firewall y que SQL Server acepte el método de autenticación elegido.

El usuario no ve un reporte+

Comprueba que el reporte y la conexión estén activos, y que el reporte esté marcado en los permisos de ese usuario.

Una lista de opciones aparece vacía+

Ejecuta la consulta de opciones directamente en SQL Server y verifica que la columna configurada como valor exista en el resultado.

Error al publicar dentro de /publish+

La carpeta publish/** debe permanecer excluida de los elementos del proyecto para evitar que una publicación anterior se incluya recursivamente.
